Documentation

A manual covering the full install path and every configuration category the backend reads. For a quick start, see the setup guide on the overview page.

Install

Prerequisites

  • JDK 21
  • Node.js 24.15 and npm 11.12.1 (for frontend development)
  • Docker with Compose v2 (docker compose)
  • OpenSSL (for generating production secrets)

Local setup

Regenerate the OpenAPI-generated contracts, install frontend dependencies, then run the backend and frontend side by side. The backend needs a running Docker daemon for Dev Services, which provisions a disposable PostgreSQL instance automatically. 

# From the repo root
./mvnw -pl backend clean generate-sources
cd frontend && npm ci && cd ..

# Terminal 1 — backend, with required env vars
export GLACIER_BOOTSTRAP_TOKEN=local-bootstrap-token-development-only
export GLACIER_SECURITY_SESSION_SECRET=local-session-secret-development-only
export GLACIER_IMAGE_FILESYSTEM_ROOT=/tmp/glacier-notes-dev-images
./mvnw -pl backend quarkus:dev

# Terminal 2 — frontend (proxies /api to :8080)
cd frontend && npm start
# Open http://localhost:4200

GLACIER_BOOTSTRAP_TOKEN and GLACIER_SECURITY_SESSION_SECRET must each be at least 32 non-whitespace characters (see Bootstrap & admin secrets and Session & security). To exercise the admin backup dashboard locally, also set GLACIER_BACKUP_ENABLED=true, GLACIER_BACKUP_DIRECTORY, and GLACIER_BUILD_IDENTIFIER.

Production setup

Generate real secrets as files rather than environment variables — the Compose file mounts them as Docker secrets so they never appear in process listings or container environment dumps. Each secret must be 32–512 non-whitespace characters. 

cp .env.example .env
mkdir -p deployment/secrets
openssl rand -base64 36 > deployment/secrets/database-password.txt
openssl rand -base64 36 > deployment/secrets/bootstrap-token.txt
openssl rand -base64 48 > deployment/secrets/session-secret.txt
chmod 600 deployment/secrets/*.txt

docker compose up --build --wait
# Open http://127.0.0.1:8080

base64 -w0 output length scales roughly 4/3 with input bytes, so 36 and 48 random bytes comfortably clear the 32-character minimum with room to spare. Edit .env to change bind addresses, ports, or the public base URL — see the configuration reference below for every variable it can set.

First administrator

On a fresh instance, create the first administrator account with the bootstrap token from deployment/secrets/bootstrap-token.txt (or GLACIER_BOOTSTRAP_TOKEN in local dev). Send it as the X-Bootstrap-Token header: 

curl -X POST http://127.0.0.1:8080/api/v1/setup/administrator \
  -H "Content-Type: application/json" \
  -H "X-Bootstrap-Token: $(cat deployment/secrets/bootstrap-token.txt)" \
  -d '{
    "username": "admin",
    "email": "admin@example.com",
    "displayName": "Administrator",
    "language": "en",
    "password": "a long, unique passphrase"
  }'

Response on success:

{
  "initialized": true,
  "initializedAt": "2026-07-25T12:00:00Z"
}

Passwords must be 12–128 characters, contain no whitespace, and not appear on the built-in common-password denylist. Setup can also be checked without attempting it via GET /api/v1/setup/status, which returns {"setupRequired": true|false}. Bootstrap attempts are rate-limited: 5 failed attempts within a 900-second window trigger a 900-second lockout (see Bootstrap & admin secrets). Once an administrator exists, the endpoint refuses further use — subsequent admins are created from the admin user-management page.

Optional S3 / MinIO storage

Image storage defaults to the local filesystem. To exercise the S3-compatible backend locally, layer the MinIO overlay on top of the base Compose file. This starts a MinIO server, provisions the bucket, and switches the app's image backend to S3. 

openssl rand -base64 24 > deployment/secrets/s3-access-key.txt
openssl rand -base64 32 > deployment/secrets/s3-secret-key.txt
chmod 600 deployment/secrets/s3-*.txt

docker compose -f compose.yaml -f compose.minio.yaml up --build --wait
# MinIO console: http://127.0.0.1:9003

The image storage backend is immutable after the first image upload — choose FILESYSTEM, POSTGRESQL, or S3 before any note has an attached image. See Image storage for the full variable list.

Upgrading & stopping

Flyway migrations run automatically at startup, so upgrading is a rebuild-and-restart. Application health can be checked on the private management port before routing traffic: 

# Rebuild and restart with the latest image
docker compose up --build --wait

# Liveness / readiness (management port, kept off the public network)
curl http://127.0.0.1:9000/q/health/ready

# Stop, preserving volumes
docker compose down

# Stop and permanently delete all data
docker compose down --volumes

Configuration reference

Every variable below is read directly by the backend or the Compose deployment. Defaults apply whenever a variable is unset. *_FILE variables point to a file whose contents are read at startup — prefer these over the bare variable for anything secret.

Database

VariableDefaultDescription
GLACIER_DATABASE_URL—JDBC URL, e.g. jdbc:postgresql://postgres:5432/glacier_notes
GLACIER_DATABASE_USERNAME—PostgreSQL role name
GLACIER_DATABASE_PASSWORD_FILE—Path to a file containing the database password
 
GLACIER_DATABASE_URL=jdbc:postgresql://postgres:5432/glacier_notes
GLACIER_DATABASE_USERNAME=glacier_notes
GLACIER_DATABASE_PASSWORD_FILE=/run/secrets/database_password

Bootstrap & admin secrets

GLACIER_BOOTSTRAP_TOKEN_FILE—Path to a file containing the bootstrap token instead
failure-limit5Failed attempts allowed within the window (not env-configurable)
window-seconds900Rolling window for counting failures

GLACIER_BOOTSTRAP_TOKEN_FILE=/run/secrets/bootstrap_token

Session & security

VariableDefaultDescription
GLACIER_SECURITY_SESSION_SECRET—HMAC key for session token hashing, 32–512 non-whitespace characters
GLACIER_SECURITY_SESSION_SECRET_FILE—Path to a file containing the session secret instead

Session tokens are opaque and random; only a keyed hash is persisted. Rotating this secret invalidates every existing session. 

GLACIER_SECURITY_SESSION_SECRET_FILE=/run/secrets/session_secret

Two-factor authentication

VariableDefaultDescription
GLACIER_MFA_ENABLEDfalseOffers each account an optional TOTP second factor
GLACIER_MFA_ENCRYPTION_SECRET—Key material for encrypting enrollments, 32–512 non-whitespace characters — required when enabled
GLACIER_MFA_ENCRYPTION_SECRET_FILE—Path to a file containing the encryption secret instead

The feature is off by default and opt-in per account: enabling it lets users add an authenticator app and ten single-use recovery codes, and never obliges them to. Enrolled accounts sign in in two steps and re-confirm sensitive changes with a code.

Stored enrollments are encrypted with a key derived from this secret, which is never written to the database or to a backup archive. Back it up with your other deployment secrets: restoring a database without it locks every enrolled account out, and changing it has the same effect until those accounts enroll again. 

GLACIER_MFA_ENABLED=true
GLACIER_MFA_ENCRYPTION_SECRET_FILE=/run/secrets/mfa_encryption_secret

Backups

VariableDefaultDescription
GLACIER_BACKUP_ENABLEDfalseEnables the automated backup job and admin dashboard
GLACIER_BACKUP_DIRECTORY/var/lib/glacier-notes/backupsOutput directory — protect it externally, it is not encrypted
GLACIER_BUILD_IDENTIFIERunknownRecorded in backup metadata to identify the producing build

Backups are started from Administration → Backups and written as a ZIP containing the PostgreSQL database (content and authentication hashes), image objects, non-secret instance settings, a manifest, version information, and SHA-256 checksums. They intentionally exclude database credentials, SMTP passwords, S3 credentials, bootstrap tokens, and cryptographic keys — treat completed archives as highly sensitive anyway, since they contain user content. The full restore runbook lives in docs/BACKUP_RESTORE.md. 

GLACIER_BACKUP_ENABLED=true
GLACIER_BACKUP_DIRECTORY=/var/lib/glacier-notes/backups
GLACIER_BUILD_IDENTIFIER=2026.07.25

HTTP body limits

VariableDefaultDescription
GLACIER_HTTP_DEFAULT_MAXIMUM_BODY_BYTES10485760 (10 MiB)Cap on ordinary API request bodies
GLACIER_HTTP_MULTIPART_OVERHEAD_BYTES1048576 (1 MiB)Allowance added on top of upload/import maximums for multipart envelopes
GLACIER_HTTP_ABSOLUTE_MAXIMUM_BODY_BYTES1611661312 (~1.5 GiB)Outer ceiling enforced by Quarkus — raising any upload limit requires raising this too

The absolute ceiling must stay at least the multipart overhead above the largest configured upload limit (currently the portable-import maximum, see Portable transfer limits). 

GLACIER_HTTP_DEFAULT_MAXIMUM_BODY_BYTES=10485760
GLACIER_HTTP_MULTIPART_OVERHEAD_BYTES=1048576
GLACIER_HTTP_ABSOLUTE_MAXIMUM_BODY_BYTES=1611661312

Portable transfer limits

VariableDefaultDescription
GLACIER_TRANSFER_MAXIMUM_UPLOAD_BYTES1610612736 (1.5 GiB)Maximum .glacier.json import size

Network & management

VariableDefaultDescription
GLACIER_PUBLIC_BASE_URLhttp://localhost:8080Canonical URL used in email verification/reset links and to decide whether session and CSRF cookies get the Secure flag (based on the URL scheme). Overridable at runtime via Administration → Instance settings.
GLACIER_HTTP_BIND127.0.0.1Host interface Compose binds the main application port to
GLACIER_HTTP_PORT8080Host port for the main application
GLACIER_METRICS_ENABLEDtrueEnables Micrometer and the Prometheus scrape endpoint
GLACIER_MANAGEMENT_BIND127.0.0.1Host interface Compose binds the management port to
GLACIER_MANAGEMENT_PORT9000Health checks, metrics — never publish this port

The management port serves /q/health/ready, /q/health/live, and /q/metrics. Keep it bound to 127.0.0.1 or an internal network only. When deploying behind a TLS-terminating reverse proxy, set GLACIER_PUBLIC_BASE_URL to the externally visible https:// address — otherwise session cookies are issued without the Secure flag. 

GLACIER_PUBLIC_BASE_URL=https://notes.example.com
GLACIER_HTTP_BIND=127.0.0.1
GLACIER_HTTP_PORT=8080
GLACIER_METRICS_ENABLED=true
GLACIER_MANAGEMENT_BIND=127.0.0.1
GLACIER_MANAGEMENT_PORT=9000
